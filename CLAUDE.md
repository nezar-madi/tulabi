# CLAUDE.md — tulabi (طلابي)

Handoff notes for AI coding sessions. Read this first, then `docs/spec.md` (the approved spec, in Arabic; it is the source of truth).

## What this is

A platform for independent instructors in Libya (tulabi.ly). Each instructor has a public page `tulabi.ly/{slug}` with their classes; students sign up by phone and ask to join a class; the instructor accepts them and records payments by hand (DPay / MyPay later). An admin approves instructors.

- **Sister product of rqmana** (`C:\laragon\www\center-saas`, multi-center SaaS for training centers). Same stack and design system, but **one database and no tenancy**: no `TenantManager`, `IdentifyTenant`, per-center databases or panel host. Copy pieces from rqmana when needed, never its tenancy.
- **Stack:** Laravel 13, Inertia v2, Vue 3 `<script setup>`, Vuetify 4, vue-i18n, Ziggy, `giggsey/libphonenumber-for-php`. PHPUnit (not Pest), sqlite in memory for tests.
- **Phase:** 0 (foundation), 1 (accounts), 2 (instructor page and classes), 3 (join requests, student side) and 4 (payments and receipts) are done. Phase 5 (before launch: privacy and terms, account deletion, security review, browser tests) waits for the owner. The phases are listed in `docs/spec.md` §8.
- **Work is local only** for now: no server, no staging, no GitHub remote. Commit locally; never push without asking.

## Decisions from the spec (don't undo without asking)

- **Libya only:** Arabic only (RTL), currency **LYD** (`App\Support\Currency`), time zone **Africa/Tripoli**, Libyan mobile numbers only.
- **Sign-in is phone + password for everyone**; email is optional. **One account per phone number.** The instructor role is added to an existing account after admin approval; an instructor can also be a student of another instructor.
- Instructor page is a **path** (`/{slug}`), not a subdomain. Slugs: lowercase English letters, digits and dashes, with reserved words (admin, login, ...).
- Instructors **apply**, the admin accepts or rejects (throughout the beta).
- **Forgotten password:** the instructor issues a reset link for their students, the admin for instructors; the link is sent with a WhatsApp button (wa.me). Anyone with an email can reset by email. Links are single use and expire after one hour. The only text message is the sign-up code (below).
- Classes are in person (address) or online (meeting link **shown only to accepted students**).
- **Payments are voided, never deleted** (with a reason); amount and date are locked after recording; a voided receipt shows «ملغى». Receipt numbers `TL-YYYYMMDD-NNNN` from a per-instructor counter that never goes backwards. Canceled classes owe nothing and take no payments.
- Class capacity is a warning only.
- Admin accounts are separate and use a TOTP second factor (as rqmana's panel).
- Abuse protection: the phone is checked by a code at sign-up, rate limits per IP and per phone (each code is a paid message), reCAPTCHA on the phone step, and the instructor accepts each student.
- Account deletion: the account goes; its payments stay without name or phone (the instructor's books stay correct).
- Activity log kept 14 days (as rqmana). Certificates, e-payment, a marketplace, attendance, SMS and a mobile app are out of scope (spec §7).
- Open: the logo (a text logo «طلابي» until then: `resources/js/Components/BrandMark.vue`, and the `.brand` mark in the Blade pages), the list of Libyan cities.

## Accounts (phase 1)

- **Guards:** `web` = `User` (phone + password), `admin` = `Admin` (email + password + TOTP, routes in `routes/admin.php` under `/admin`, names `admin.*`). User routes use `auth:web` / `guest:web` explicitly and code reads `$request->user('web')`; an admin session never counts on the user side. Logging out of the admin invalidates the whole session (the user side too).
- **Sign-up** (`/register`, owner's decision 2026-11-02): three steps for students and instructors alike. (1) the phone only (+ reCAPTCHA, `App\Support\Recaptcha`, skipped without keys outside production), (2) a six-digit code sent by message (`App\Support\PhoneVerifications`: 10 minutes, 5 tries, resend after 60 s, kept as an HMAC in `phone_verifications`), (3) password + confirmation; then signed in. Steps live in the session (`register.phone`, `register.verified`, valid 30 min). Everything else (name, email) is filled in from «حسابي»; until a name is set `User::name` returns the phone (use `hasName()`). **«انضم كمدرّس»** (`/join`): a visitor is sent to `/register?for=instructor` and lands back on `/join` after the password; the form asks for specialty, city, bio and, if the profile has no name, the name. One pending application at a time; after a rejection they may apply again.
- **Classes are called «فصول» in the UI** (owner's decision; it was «دورات» for a day on 2026-11-03 and went back to «فصول» on 2026-11-04: use «فصل» everywhere, never «دورة»; code, routes and tables keep `class`). Class form: description required; in-person classes need a Google Maps link (`map_url`, `App\Rules\GoogleMapsUrl`: https only, google.com/maps, maps.google.*, maps.app.goo.gl, goo.gl/maps) and the written place is optional; a promotional image (`image_path`, `App\Support\ClassImage`: re-encoded 1200x750 JPEG on the public disk, `class-images/{instructor}/`) is optional. Dates and times use rqmana's `FormPlainDatePicker` / `FormPlainTimePicker` (copied unchanged).
- **Students page** (`/teach/students`, `Teach\StudentController`, `App\Support\InstructorStudents`): everyone ever accepted in the instructor's courses, one row per person (name or phone, WhatsApp, paid/remaining, expandable per-course rows with payments, remove and a password link). Tabs حاليون/سابقون/الكل, a course filter and a name/phone search live in the query string. Built in PHP from the instructor's own enrollments and paged by hand (15 per page): fine for one instructor's roster, rewrite as a query if a roster ever reaches thousands. The actions reuse the existing enrollment routes (`back()` returns to the list).
- **Programs («البرامج التدريبية», as rqmana's class templates, simplified for one instructor)**: `programs` table (name unique per instructor, required SafeHtml description, optional poster, `is_active`, `is_published`, `is_featured`), `Teach\ProgramController` at `/teach/programs`. **A program is a course template** (owner's decision 2026-11-04): on a *new* course, choosing a program fills the title, the description and the image from it (the form does it, without overwriting what the instructor already typed; the server copies the poster as the course's own image unless `no_template_image` is sent or an image is uploaded). The link stays in `classes.program_id`. A course may belong to one of the instructor's own *active* programs (`classes.program_id`; a course already in a program that was stopped later may stay). A program with courses cannot be deleted (stop it or move its courses). Public: `/{slug}/programs` and `/{slug}/programs/{id}` (published + active only; the owner can preview a hidden one), a programs section on the instructor page, and a program link on the course page. The poster reuses `ClassImage`. rqmana's departments, levels and subjects are left out on purpose.
- **Days of study** (as rqmana's three types): `classes.schedule_type` is `daily`, `weekly` (`days`, at least one weekday; for a period shorter than a week the days must occur in it) or `manual` (`manual_dates`, a list of Y-m-d inside the period; `ends_on` follows the last date when none is given). Saving drops what belongs to the other types. Text on the public pages: `ClassText::schedule()` and `formatScheduleDays()` in `classFormat.js` (same wording). The multi-date field is rqmana's `FormPlainDatesPicker`, copied unchanged.
- **The page's «نبذة» is sections** (`instructors.bio_sections`, a list of {title, body}; `App\Support\AboutSections`): «من أنا» first (always there, may be empty, cannot be removed), then up to 7 more the instructor adds («مؤهلاتي», «الخبرة العملية»... offered as one-click suggestions), reorderable. Bodies are rich text through `SafeHtml`; empty extra sections are rejected, empty ones are never shown publicly. `instructors.bio` is kept as the plain text of the first section (the page's lead line, meta description and the dashboard's setup step); an instructor with only an old `bio` sees it as «من أنا» until they save.
- **Payments page** (`/teach/payments`, `Teach\PaymentOverviewController`): every payment of the instructor across courses, newest first, 25 per page, filtered in the query string by period (days in Libya; presets this month / last month / this year / custom), course, method, status (valid by default, voided, all) and a search on student name, phone or receipt number. Totals (collected, count, by method) never count voided payments. «تسجيل دفعة» there lists only accepted students who still owe and posts to the usual per-enrollment route; edit and void reuse `PaymentController`.
- **Content of a program and of a class (one shape, owner's decision 2026-11-04)**: a plain-text `description` («نبذة عن الفصل/البرنامج», a textarea, max 5000), three bullet lists `learn` (ماذا سيتعلم الطالب), `requirements` (المتطلبات) and `audience` (الفئة المستهدفة) (each up to 15 items of 200 characters), and an optional `promo_video_url`. `App\Support\CourseContent` cleans and validates them; the form block is `Components/CourseContentFields.vue` (+ `ListField.vue`); public pages use `partials/course-content.blade.php`. Nothing here is HTML: descriptions are escaped and shown with their line breaks (**never `v-html`**: a test fails on any `v-html` in `resources/js`) (the old rich-text descriptions were converted to text by the migration). The video is a YouTube, Vimeo or Dailymotion link only (`App\Support\VideoEmbed`, `App\Rules\EmbeddableVideoUrl`): the player address is rebuilt from the video id (youtube-nocookie for YouTube) and never taken from what was typed.
- **Creating a class** is «فصل جديد» or «من برنامج تدريبي» (a toggle, as in rqmana). From a program, the title, description, lists, video and image are copied in (the server copies the poster as the class's own image unless `no_template_image`); `/teach/classes/create?program=ID` arrives with the program chosen.
- **A class or a program has a promotional image OR a promotional video, never both** (owner's decision 2026-11-04). Neither is fine while it is a draft or hidden; **one of them is required to show it to visitors**: a class cannot be published without `image_path` or `promo_video_url` and cannot end up with neither while published/closed/suspended (swapping one for the other in one save is fine); a program cannot be `is_published` without one. `TeachingClass::hasMedia()` / `Program::hasMedia()`; `TeachingClass::scopePubliclyVisible` and `Program::scopePublic` accept either. Both at once is refused (`classes.media_either`, `programs.media_either`). The forms use `Components/PromoMediaChoice.vue` (two cards, tap the chosen one again for neither; the image picker stays in each form; the video field is no longer in `CourseContentFields`). A new class from a program copies the program's image only when it has no video of its own; a program's video link is copied into the class form. **A program's own minimums** (owner's decision 2026-11-04, programs only; a class has none): name 3+ letters, description 20+ (`CourseContent::PROGRAM_DESCRIPTION_MIN`), and each point of its three lists (optional lists) 3+ (`PROGRAM_ITEM_MIN`); the wizard checks them before «التالي», pointing at the point (`learn.N`). After creating a program, its page opens once with the same success dialog as a class (`Components/CreatedDialog.vue`, flash `programCreated`). **Images are kept whole** (owner's decision 2026-11-05): `ClassImage::render` only scales a picture down to fit 1600 px on its longest side (no 16:10 crop any more), the form's two previews (`.cf-image`, `.cf-preview__media`) use `object-fit: contain`, while the cards and public pages frame it with `cover` themselves; images saved before this day stay cropped to 16:10. A video-only class or program shows a play-icon placeholder on cards (no thumbnail: no request to YouTube before the visitor presses play); the public page embeds it (`VideoEmbed`). Old data with both keeps the image when edited and drops the video on save.
- **«تعليق البدء تلقائيًا»** (`classes.auto_suspend`, `min_seats` ≤ seats): checked **once**, when a published/closed class reaches its start date (Libya): with fewer `accepted` students than `min_seats` it becomes `suspended` («معلّق»); either way `classes.start_checked_at` is stamped and the class is never checked again for that start (a student leaving mid-course, an ended class, or switching the option on after the start never suspends). Moving the start to a later date clears the stamp; publishing on or after the start date and restarting stamp it (a restart is the instructor's decision to run with the students it has). `ClassLifecycle::checkStart` runs hourly (`classes:check-start`, `routes/console.php`; **production cron must run `schedule:run`**) and when the instructor opens their dashboard, classes list or a class. A suspended class is hidden from visitors, takes no requests, can be edited or canceled, and restarts with `POST /teach/classes/{id}/reactivate` (a new start date, today or later, a weekly class on one of its days; the end date and hand-picked dates shift by the same number of days).
- **Messages:** `App\Support\Sms\SmsSender`, chosen by `SMS_DRIVER` (config `tulabi.sms.driver`). Only `log` exists (writes the code to `storage/logs/laravel.log`, local work only). **A real gateway must be added and mapped in `AppServiceProvider` before launch**; the provider is not chosen yet.
- **Instructor = a row in `instructors`** (`User::isInstructor()`), made by `App\Support\InstructorApplications::accept()`; `slug` stays null until phase 2. Accepting shows the admin a WhatsApp button with a welcome message (`App\Support\WhatsApp`, wa.me links only; tulabi sends nothing itself).
- **Suspending** is on the account (`users.status`); `EnsureAccountIsActive` signs a suspended account out on its next request, and login says it is suspended only after the right password. `instructors.status` exists for later (switching teaching off) and is not set from the admin yet.
- **Password reset links** (`App\Support\PasswordResetLinks`, table `password_reset_links`): only the token's sha256 is stored, one hour, single use, a new link cancels older unused ones, and a suspended account's link does not work. Made by the admin (students and instructors lists), by email from «نسيت كلمة المرور» (only when the account has an email; the answer is the same for every phone), and later by instructors for their students (`ISSUER_INSTRUCTOR`). Laravel's own password broker and `password_reset_tokens` table are not used.
- **No double submits** (owner's decision 2026-11-04): `resources/js/utils/submitGuard.js`, installed in `app.js`, refuses any non-GET Inertia visit while another is in flight (a double click, a repeated Enter, two different buttons) and marks `html[data-busy]` after 150 ms so buttons dim (`app.css`); it covers every action button without per-button code (a spec holds the cases). Plain Blade forms (the public join request) are sent once by the script in `site/layout.blade.php`. **The save button of an existing class or program is off while nothing has changed** (`form.isDirty`; Enter does nothing either; a new one is unaffected). **There are no breadcrumbs** anywhere (`PageIntro` and the public pages' head have none; the sidebar is the way around; owner's decision 2026-11-05). **Deleting asks first** with `Components/ConfirmDialog.vue` (program, draft class, profile photo); the browser's `window.confirm` is still used by the student's withdraw and the admin's suspend.
- **Rate limits** (`AppServiceProvider`): login 5 per phone+IP and 30 per IP per 10 minutes (in the SessionControllers), sign-up and join 10 per IP per hour, forgot-password 3 per phone and 10 per IP per hour, creating or saving a class 30 per minute per account (`class-save`).
- **Admins:** `php artisan admin:create {email}` (asks the password, 12+ characters); the authenticator is set up at first login (`EnsureAdminTwoFactor`). `php artisan admin:two-factor-reset {email}` for a lost phone. The admin 2FA code and its Vue pages (`Pages/Admin/TwoFactor`) are rqmana's panel code with names changed; their Arabic text is still written in the pages, as in rqmana. `Setting::APPLICATIONS_NOTIFY_EMAIL` (admin «الإعدادات») gets an email per new application.
- Local data: `php artisan migrate:fresh --seed` makes sample accounts (password `password`) and, locally only, `admin@tulabi.test` (sets up its authenticator at first login).
- The skeleton's users migration was edited in place (phone, status; no `password_reset_tokens`) because nothing has been deployed yet. From the first deploy on, never edit an old migration.

## Instructor page and classes (phase 2)

- **Instructor area** `/teach` (`EnsureInstructor`): الرئيسية (setup checklist, counts, coming classes), فصولي, صفحتي. Every `{class}` is checked twice: the FormRequest (`Requests\Teach\InstructorRequest::authorize()`, 403) and the controller (`FindsOwnClass::ownClass()`, 404). Queries start from `$instructor->classes()`. `tests/Feature/Teach/ClassTest.php` holds the isolation tests; add one for every new class route.
- **Public pages** `routes/pages.php`, loaded last: `/{slug}` (`instructors.show`) and `/{slug}/classes/{id}` (`classes.show`). A page is public when the slug is set, `instructors.status` is active and the account is active (`Instructor::scopePublic`). Visitors see published and closed classes that have not ended; the owner also sees their drafts (with a banner); canceled classes are seen by nobody. **`meeting_url` never goes to a public page** (`InstructorSite::course()` has no such field); it is for accepted students (phase 3).
- **Slugs** (`App\Support\InstructorSlug`): lowercase English letters, digits and single dashes, starting with a letter, 3-40 characters, chosen by the instructor in «صفحتي» (null until then; publishing a class needs it, and it cannot be cleared while classes are public). The route pattern excludes `RESERVED`; **add every new top-level path to `RESERVED`** (`PublicPagesTest` fails otherwise).
- **Classes** = model `TeachingClass`, table `classes` (`Class` is reserved in PHP; Vue props carrying a class are named `item`, since `class` is not a usable prop name). Status changes only through `App\Support\ClassLifecycle`: draft → published ⇄ closed; any → canceled (final, read-only, optional reason); deleting (soft delete, with its image and the requests never accepted) is for a draft, or a canceled / ended class that never had an accepted student or a payment, voided ones included (`TeachingClass::canBeDeleted()`, owner's decision 2026-11-05); a class that is running is canceled instead. Class dates are DATE columns (calendar days in Libya, no time zone) and days are Carbon weekday numbers (0 = Sunday), shown Saturday first. Price is `decimal(12,3)` in LYD (`currency_code` stored per class). Seats are a warning only.
- **Descriptions** go through `App\Support\SafeHtml::description()` (copied from rqmana with `tests/Unit/SafeHtmlTest.php`) and are edited with rqmana's `FormPlainRichText` (tiptap).
- **Photo** (`App\Support\InstructorPhoto`): decoded with GD and saved again as a 512px square JPEG on the `public` disk (`instructors/{id}/`), the old file deleted; served as `/storage/...` (run `php artisan storage:link`). Links (`App\Support\ProfileLinks`): up to 5 http(s) URLs, icon chosen from the host.
- The «اطلب الانضمام» button on a class page is shown disabled until phase 3.

## Join requests and the student side (phase 3)

- **Enrollments** (`Enrollment`, table `enrollments`): **one row per student and class** (unique), changed only by `App\Support\Enrollments` with conditional updates: requested → accepted | rejected; accepted → canceled (the instructor removes the student, optional reason); requested | accepted → withdrawn (the student); rejected / withdrawn / canceled → requested again on the same row. Nothing on the model is mass-assignable.
- **Fee:** copied from the class price at the first acceptance and never changed by a later price edit; a student accepted again keeps the first fee (rqmana's "re-enrolling continues the original fee"). Payments arrive in phase 4.
- **A canceled class** shows its open places as «ملغى» without changing the rows (`Enrollment::displayStatus()`, like rqmana's `billingStopped()`), so it owes nothing; its requests cannot be accepted and leave the instructor's list.
- **Requests** only for a class that is published and not ended, of a public instructor, and not the student's own class (`TeachingClass::acceptsRequests()`). A visitor pressing «اطلب الانضمام» goes through `GET /classes/{id}/request` (auth), so after signing in they land back on the class page with `?request=1` and the box open.
- **Meeting link** reaches the student only in `EnrollmentPresenter::forStudent()` and only when `isActiveMember()` (accepted, class not canceled). Public pages never have it. It is optional and can change any time (owner's decision 2026-11-03: badge + WhatsApp, no email): a change sets `classes.meeting_url_changed_at`, students see «تم التحديث» for `MEETING_URL_NEW_DAYS` (7), and the instructor gets «أرسل الرابط عبر واتساب» (`WhatsApp::share()`, wa.me without a number) on the edit page (highlighted right after the change) and the class students page.
- **Required class fields** (owner's list, 2026-11-03): title, description, one item in each of the three lists, type (+ map link if in person), both dates, days, both times, price (0 = free), seats (0 = no limit, stored null), and the program when «من برنامج تدريبي» is chosen (`from_program`). Optional: video, written place, meeting link; the image only to publish.
- **Class rules from the review (owner's decisions 2026-11-03):** no past dates (a new class starts and ends today or later; an existing class keeps the dates it has but a changed date cannot go into the past); a weekly class starts on one of its days (checked when the start or days change); hand-picked dates are the period (`starts_on`/`ends_on` = first/last date); an ended class cannot be published and its page is 404 for visitors (the owner still sees it); **the price is fixed once a student has joined** (a request waiting or accepted, or anyone accepted before: `TeachingClass::priceIsLocked()`); no accepting after the class ended (rejecting still works); changing the dates, hours, place or type of a class with accepted students sets `classes.schedule_changed_at` (students see a notice for 7 days) and offers the instructor a WhatsApp message with the new schedule (`ClassPresenter::scheduleShareUrl`); **a suspended class frees its hours** (`ScheduleClash::ACTIVE` = published, closed; its restart is checked against everything); deleting a draft deletes its image file; **an ended class cannot be canceled** (it would erase what its students owe; one student's balance is let go by removing that student).
- **Student pages** `/account/classes` and `/account/classes/{enrollment}` (`StudentEnrollmentRequest`: own enrollments only). **Instructor pages** `/teach/requests` (badge = shared `auth.user.pendingRequests`) and `/teach/classes/{id}/students`; every `{enrollment}` action goes through `Teach\EnrollmentActionRequest` (enrollment in one of the instructor's classes). Isolation tests in `tests/Feature/Teach/EnrollmentTest.php` and `tests/Feature/Student/JoinClassTest.php`.
- **Instructor reset links:** only for students accepted in that class, active, and not instructors themselves (those go to the admin). The instructor sees the URL; this follows the spec (students ask their instructor). Limited to 20 per hour.
- **Email** (only to people who gave one): the instructor on a new request, the student on accept or reject. Failures are reported, never block the change.

## Payments and receipts (phase 4)

- **Payments** (`Payment`, table `payments`) are made only by `App\Support\Payments`: **voided, never deleted** (reason required; the row and receipt number stay; `deleting` is refused), **amount and date locked** after recording, only method and notes editable. Methods by hand: cash, transfer, other (`provider` and `provider_reference` stay empty until DPay / MyPay).
- **Who can be paid for:** only an accepted student of a class that is not canceled (`Enrollment::isActiveMember()`), and **never more than the remaining** (the enrollment row is locked while checking). A removed or withdrawn student, or a canceled class, owes nothing more; their past payments stay.
- **Money math** in whole dirhams (`Currency::toMillis()` / `fromMillis()`), never floats; `Currency::format()` drops trailing zeros for display. Fee − paid (not voided) = remaining (`Enrollment::remainingMillis()`).
- **Dates:** `paid_at` uses the `App\Casts\TulabiDateTime` cast (a typed `Y-m-d` = local midnight in Tripoli, stored UTC; copied from rqmana's `CenterDateTime`); not in the future, not before 2000. The dashboard's "this month" uses `TulabiClock::monthRangeUtc()`.
- **Receipt numbers** `TL-YYYYMMDD-NNNN` from `receipt_counters` (one row per instructor, locked, restarts at 1 each Libyan day, never goes backwards); unique per instructor, so two instructors can both have `TL-…-0001`.
- **Receipts** `GET /receipts/{payment}` (PDF, mPDF with `resources/fonts/Tajawal-*.ttf`, view `resources/views/receipts/payment.blade.php`): only the instructor who recorded it and the student it is for. Paid and remaining on a receipt count payments up to that one, so a printed receipt keeps saying the same thing; a voided receipt opens with «ملغى».
- **Pages:** instructor `/teach/enrollments/{id}/payments` (record, edit, void; ownership in `RecordPaymentRequest` / `PaymentRequest`), paid and remaining on the class students page, «المحصّل هذا الشهر» and «المتبقي على الطلاب» on the dashboard; student payments in the class detail and «دفعاتي» `/account/payments`. Isolation tests in `tests/Feature/Teach/PaymentTest.php`.

## Conventions carried over from rqmana

- **Dates:** timestamps are stored in UTC; `config('app.timezone')` stays `UTC`. For "today", "this month" or a date a person typed, use `App\Support\TulabiClock` (Africa/Tripoli, from `config/tulabi.php`), never `now()->toDateString()`. A typed `Y-m-d` means local midnight (`TulabiClock::storeDate()`). Filter by date with `startOfDayUtc()`/`endOfDayUtc()`, not `whereDate`.
- **Phones:** normalise every phone with `App\Support\LibyanPhone::normalize()` before saving or looking up; store E.164 (`+2189XXXXXXXX`). `forWhatsApp()` gives the wa.me digits, `display()` the local form (091-2345678). Only mobiles are accepted (landlines are rejected).
- **Permissions:** every route checks access on the server. Put the check in the FormRequest `authorize()` (so 403 comes before validation) and keep the controller check as a second layer. An instructor only ever sees their own classes and their students; a student only their own enrollments. Write isolation tests for each.
- **User model:** `phone`, `password` and `status` (and any role/type column) are **not mass-assignable**. Set them with `forceFill()`/`forceCreate()` and explicit values only.
- **HTML from instructors** (class descriptions) must go through a `SafeHtml` sanitiser (copy `App\Support\SafeHtml` and `tests/Unit/SafeHtmlTest.php` from rqmana when the first rich text field arrives); it is rendered with `v-html`.
- **Text:** all UI text is Arabic, in `resources/js/locales/ar.json` (frontend, checked by `messages.spec.js`: write `@ { } |` as `{'@'}` etc.) and `lang/ar/*.php` (backend). Keep it short and plain.
- **Icons:** Tabler icons (`icon="tabler:name"`) must be registered in `resources/js/icons/tablerChrome.js`, or they render blank; `tablerChrome.spec.js` fails on an unregistered name.
- **Design: exactly rqmana's, colours included** (the owner's decision, 2026-11-02: same look and same blue; a green version was tried and dropped). rqmana's design files are copied as they are (tokens, Vuetify theme and overrides, `app.css`, form fields, layouts, the website and landing stylesheets): primary `#0D4AA8`, dark `#08286E`. **Copy further rqmana design files unchanged**, and don't invent styles rqmana doesn't have (no yellow; `#FFC24A` is only in rqmana's ads). Tokens keep the `--rq-` prefix and classes `rq-` so rqmana components copy as they are; rqmana's `--rq-blue-*` are named `--rq-brand-*` here (`--rq-green-*` is the success colour). Fonts: Alexandria and Tajawal (app: fonts.bunny.net; Blade pages: rqmana's self-hosted files in `public/fonts/site`).
- **Layouts (rqmana's):** signed-in pages (`Teach/`, `Student/`, `Account/`, `Admin/`) use `AppShell.vue` (side menu `Sidebar.vue` from `config/sidebarItems.js`, top bar, `UserMenu.vue`) with `PageIntro` headings (breadcrumb from the side menu, `useBreadcrumbs`); sign-in pages (`Auth/`, `Join/`, `Admin/Login`) use `AuthSplitLayout.vue` with `AuthCard.vue` and `CtaButton`. The admin two-factor pages are rqmana's panel pages (`layout: null`). The public pages are **Blade**, like rqmana's: the home page `resources/views/home.blade.php` (rqmana's landing: `views/landing/styles`, `icons`), and the instructor and class pages `resources/views/site/*` (rqmana's center website, data from `App\Support\InstructorSite`, Arabic dates and times from `App\Support\ClassText`). Forms use rqmana's `Components/formFields` with Inertia `useForm` errors; the one-time message is the shared `flash.status`, shown by the app shell.
- Formatting: `vendor/bin/pint` on changed PHP files.

## Running locally

```bash
composer install && npm install
cp .env.example .env && php artisan key:generate
php artisan migrate --seed          # sample accounts and classes
php artisan storage:link
npm run build                      # or: npm run dev (Vite on 127.0.0.1:5174)
php artisan serve --port=8010      # http://127.0.0.1:8010
```

`.env.example` points at `http://tulabi.test` for Laragon; the virtual host appears after Laragon reloads its sites. The local database is sqlite (`database/database.sqlite`).
